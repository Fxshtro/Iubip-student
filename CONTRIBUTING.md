# Правила работы с репозиторием

## Сообщения коммитов

Формат: `<тип>(<область>): <что сделано>`

| Тип | Когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление ошибки |
| `docs` | документация |
| `style` | оформление кода, без изменения поведения |
| `refactor` | переработка без новой функциональности |
| `test` | тесты |
| `chore` | сборка, зависимости, конфигурация |
| `perf` | производительность |
| `build` | система сборки |

Примеры:

```
feat(schedule): календарь выбора даты
fix(nav): убрать квадратную подсветку при нажатии
docs: описать правила вёрстки
chore(deps): поднять Compose BOM
```

Правила:
- заголовок до 72 символов, повелительное наклонение, без точки в конце;
- один коммит — одна законченная мысль;
- не коммитить «в процессе»: если работа не закончена, её место в отдельной ветке.

## Ветки

- `master` — рабочая ветка, только проверенный и собирающийся код;
- задача — отдельная ветка от `master`: `feat/календарь`, `fix/подсветка`;
- после слияния ветку удалять.

## Хуки (уже настроены локально)

```bash
git config core.hooksPath .githooks
```

- `.githooks/commit-msg` — не даст закоммитить сообщение не по формату;
- `.githooks/pre-commit` — не пропустит `local.properties`, `build/`, `.gradle/`, `.apk`, `.log`.

На новой машине после клонирования выполнить команду выше один раз.

## Перед пушем

```bash
./gradlew assembleDebug testDebugUnitTest
```

Красная сборка или тесты — пуш не выполнять.
